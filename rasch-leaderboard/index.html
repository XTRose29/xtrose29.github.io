Main idea

Learn a score for each solver’s ability and each node’s difficulty. Predict whether a solver can solve a node from the difference between those scores. Update the estimates as verified results arrive.

Estimate cost and runtime separately, with their own solver parameters. Test whether node difficulty helps predict them too.

Start with shared nodes evaluated by every solver. Then balance three goals: solve problems cheaply, improve uncertain estimates, and explore less-tested pairs. A tentative allocation is 60% efficient solving, 30% learning, and 10% random exploration, within an agreed budget.

Detailed math

1. Success probability

Let si be solver i’s ability, dj node j’s difficulty, and y the observed outcome: 1 for a verified proof, 0 for failure within the attempt budget.

pij = P(y = 1) = σ(si − dj)
σ(x) = 1 / (1 + exp(−x))

Only the gap matters. Adding 1 to both scores leaves the prediction unchanged. Fix the mean node difficulty at zero to anchor the scale.

2. Estimate the scores

After each batch, fit the observed outcomes by minimizing the regularized negative log-likelihood:

L = −Σobserved attempts [y log pij + (1 − y) log(1 − pij)]
　 + λs Σi si² + λd Σj (dj − μj)²

Positive λ values prevent extreme estimates when data are sparse. Use μj = 0 initially, or a centered initial difficulty estimate. This is a Gaussian-prior MAP fit. Estimate uncertainty as well; the fitted scores alone do not tell us how reliable a ranking is.

3. Cost, time, and the next evaluation

A simple starting model for expected dollars and seconds per attempt is:

Ĉij = exp(ci + βCdj)
T̂ij = exp(ti + βTdj)

Here ci and ti are separate solver parameters; the β coefficients describe how difficulty relates to each objective. Fit using successful and failed attempts. Compare against solver-only baselines to check whether sharing difficulty is useful.

Efficient-solving priority = pij / max(Ĉij, ε)
Learning priority = pij(1 − pij) Var(si − dj) / max(Ĉij, ε)

The learning score is a heuristic: favor uncertain ability–difficulty gaps near 50% success, adjusted for cost. ε is a small positive cost floor. Apply a latency limit and a total spending cap; random exploration maintains coverage.

Simple example

Suppose solver A has ability 1.5 and solver B has ability 0.5. An easy node has difficulty −0.5; a hard node has difficulty 0.5. These are illustrative numbers, not experimental results.

Predicted probability of solving a node
SolverEasy nodeHard node
A · ability 1.588%73%
B · ability 0.573%50%

A on the hard node and B on the easy node both have a gap of 1, so both have about 73% success.

Now suppose an attempt costs $2 for A and $0.50 for B. On the hard node, A gives 0.73 / 2 ≈ 0.37 expected successes per dollar, while B gives 0.50 / 0.50 = 1.00. A is more likely to solve it in one attempt; B has better predicted success per dollar.

If B’s ability on hard nodes is uncertain, testing B may also be valuable for learning. If B solves the node, the model has evidence to raise B’s ability, lower the node’s difficulty, or both; results from other solvers and nodes help distinguish those explanations.

For a first pilot, compare this sampling policy with uniform sampling under the same budget. Use a fixed evaluation set to check prediction accuracy and ranking uncertainty. Treat stable estimates and a nearly solved benchmark as separate signals; keep shared anchor nodes when adding harder problems.
